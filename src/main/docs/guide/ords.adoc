The `micronaut-datarest-ords` module consumes the AutoREST API of https://docs.oracle.com/en/database/oracle/oracle-rest-data-services/[Oracle REST Data Services (ORDS)]. ORDS exposes an Oracle Database schema over HTTP; once a table is REST enabled, it becomes a collection at `/ords/{schema-alias}/{table-alias}/` and each row a resource under it.

== Dependency

dependency:micronaut-datarest-ords[groupId="io.micronaut.datarest"]

== Configuration

The data source URL points at the REST enabled schema alias, so the repositories can append the table alias:

[configuration]
----
restdatasources:
  default:
    url: http://localhost:8080/ords/hr
----

The last path segment is the `p_url_mapping_pattern` given to `ords.enable_schema`, not the database schema name.

== How operations map to AutoREST

[cols="1,2,3"]
|===
|Operation |Request |Notes

|`save`
|`POST /{table}/`
|The created row is returned, including columns generated by the database such as identity keys.

|`findAll`
|`GET /{table}/`
|The server default page is returned, 25 rows unless configured otherwise.

|`findAll` with a `Pageable`
|`GET /{table}/?limit=&offset=&q=`
|Page size and offset become `limit` and `offset`; a sort becomes the `{"$orderby":{"column":"ASC"}}` query document.

|`findById` and `existsById`
|`GET /{table}/{id}`
|Rows are addressed by primary key. A `404` yields `null` or `false`.

|`update`
|`GET /{table}/{id}` then `PUT /{table}/{id}`
|AutoREST `PUT` replaces the whole row, so the given columns are merged into the current row first. A missing row yields `null` and nothing is written.

|`count`
|`GET /{table}/?limit=500&offset=`
|AutoREST collections report `hasMore` but no total, so rows are counted by walking the collection in windows of 500. The same walk supplies the page total whenever `hasMore` is set; a last page knows its total without it.

|`deleteById`
|`DELETE /{table}/{id}`
|The `rowsDeleted` field of the response is returned.
|===

Because AutoREST addresses rows by primary key, the `idColumn` argument of the contracts is accepted for compatibility but not used. Tables without a primary key cannot be addressed by row.

== Enabling a table

Enable the schema and the table with the `ORDS` PL/SQL package, as described in the https://docs.oracle.com/en/database/oracle/oracle-rest-data-services/[ORDS documentation]. The aliases become the path segments of the URL:

[source,sql]
----
begin
  ords.enable_schema(p_enabled => true, p_schema => 'HR',
                     p_url_mapping_type => 'BASE_PATH', p_url_mapping_pattern => 'hr',
                     p_auto_rest_auth => false);
  ords.enable_object(p_enabled => true, p_schema => 'HR',
                     p_object => 'BOOKS', p_object_type => 'TABLE', p_object_alias => 'books',
                     p_auto_rest_auth => false);
  commit;
end;
----

With `p_auto_rest_auth` set to `true`, ORDS requires authentication. Configure the data source's HTTP client to send the credentials or token, as described in the <<quickStart>>.

== Limitations

* AutoREST returns column names in lower case, whatever the case in the database. Name the fields of your row types accordingly.
* `count` and page totals on non-final pages cost one request per 500 rows, so they are proportional to the table size.
* `findAll` without a `Pageable` returns only the server default page. Pass a `Pageable` to read more.
* `update` is two requests and is not atomic: a concurrent write between the read and the `PUT` is overwritten.
* Only AutoREST table and view endpoints are covered. ORDS REST modules, batch loads and `q` filtering are not exposed by the repositories; use the data source's `HttpClient` from api:datarest.core.clients.RestDataSourceClient[] for those.
